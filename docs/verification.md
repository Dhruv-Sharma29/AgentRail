## Separate review pass

Reviewed tests first, then correctness, readability, module boundaries, security, query bounds and recovery behavior using code-review-and-quality and agent-security-review.

- Ownership derives from the persisted security principal. Run starts, reads, cancellation and history are owner-scoped; missing/unowned resources return 404. Unknown ownership/input fields fail validation. Mutations retain CSRF protection.
- A run's graph version, input and execution plan are immutable through the API. Agent settings freeze the allowed tools and bounded goal. Unconfigured AI/approval/condition/branching nodes are refused at start; approval nodes cannot be silently bypassed.
- Idempotency keys bind owner, workflow, exact input and explicit version. A workflow lock and database uniqueness constraint prevent duplicate starts. A run lock serializes worker advances, cancellation and replay snapshots. Read traces use a repeatable-read transaction.
- Local handlers have no shell, SQL, arbitrary filesystem, URL, model or external ticket capability. Issue text remains data. Proposal policy checks the whole batch before effects, registered names, workflow permissions, strict typed arguments, persisted role and server issue/category context. Frozen arguments are revalidated before dispatch. Graphs, inputs, proposal bytes, batches, usage and elapsed budgets are bounded.
- Step outcomes, run checkpoints and audit records commit atomically. Rollback leaves the prior checkpoint intact; restart discovers pending/running work. Live intent reservations commit before transaction-free dispatch; result rollback retains the reservation and unresolved intent. Cancellation abandons the intent and ignores late results. Expired uncertain requests are never automatically replayed. No claim of exactly-once external execution or provider billing is made.
- Audit events omit issue text and credentials. Run/step inputs, outputs and accepted proposals contain issue content and are restricted to their owner. Rejected raw proposals are discarded. Handler/planner error codes omit exception details. The initial audit scope covers execution, not all security activity; policy APPROVED is not a human approval.
- Existing schema/version definitions remain compatible. Optional agent settings preserve old saved graphs; V3 defaults old runs to DETERMINISTIC with zero planner/tool usage. V4 adds nullable intents/model identity and zero token defaults. Unconfigured nodes cannot execute. Spring AI 1.1.8 adds only its OpenAI/model/commons/template/retry modules; no provider starter auto-configuration, vector store, embeddings, document ingestion or MCP capability is enabled. Spring's August 2026 advisories for [Transformers resource caching](https://spring.io/security/cve-2026-59294/), [ONNX substitution](https://spring.io/security/cve-2026-47852/) and [PDF ingestion](https://spring.io/security/cve-2026-47851/) were checked; the corresponding component classes were absent from the executable jar. This bounded dependency review is not a full dependency vulnerability audit. Recheck dependencies before adding those capabilities.
- Structural discovery used codebase-memory and cited-path coverage checks, with source inspection for incomplete Java call relationships and new/changed files. The refreshed index reported partial SQL parsing on V3/V4 lines 2–3; both migrations were read directly and exercised by PostgreSQL tests. The ignored credential file was excluded from indexing. Graph coverage remains a best-effort signal.

## Limits and follow-up work

The current engine supports bounded local actions, deterministic proposals and opt-in Gemini/OpenAI planning in one linear chain. Live planning has persisted intents, request/result transaction separation, usage reservations and deadlines. The live Gemini path passed; the OpenAI path remains blocked by quota. Classification itself remains rule-based. External ticket creation, independent reviewer roles, branching and remote-effect reconciliation remain future work. Durable owner approvals and bounded pure local action retries are implemented. The serial worker can delay other runs during a provider request; wider concurrency needs a separate scheduling increment. Tool catalog persistence/administration, authentication/administration audits, registration, password rotation, login throttling, retention/encryption policy and production ingress remain future work.

Container image builds, a full running Compose deployment and remote deployment have not been verified. The process restart test does verify the application jar against PostgreSQL; it does not verify the production container image. CI configuration is committed, but a hosted CI run is not claimed.
